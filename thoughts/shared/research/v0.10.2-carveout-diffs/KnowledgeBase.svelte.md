## Candidate ports / follow-ups

1. **Incremental checksum-diff local-folder sync** (row 13, diff lines ~476-759) — upstream's biggest genuine improvement: hash local files, diff against the KB, upload only added/modified files, delete removed ones, mirror folder structure — vs. the fork's current "reset KB, reupload everything" `syncDirectoryHandler` (`KnowledgeBase.svelte:820-836`). Could likely be retrofitted onto the fork's flat path-embedded-filename model *without* adopting the full directory-object CRUD system. Worth a dedicated fast-follow.
2. **"Copy KB ID" button** (row 22) — trivial, zero-risk, generally useful; no directory dependency.
3. **File rename UI** (row 15) — `renameFileById` already exists as an additive endpoint (D3); only a UI affordance is missing.
4. **Standalone "Reset knowledge base?" confirmation** (row 32) — small safety-net improvement, decoupled from the sync confirm dialog.
5. **`i18n` `Writable<i18nType>` typing** (row 1) — trivial TS-strictness win.
6. **"Search file content" toggle** (`includeContent`, row 25) — medium priority; check backend search-relevance/latency cost of content search before wiring up.
7. **External read-only KB "Test Query" panel** (row 23) — only relevant if/when a genuinely query-only external KB source type is needed; fork's `integration_providers`/cloud-badge system already covers overlapping read-only/managed-source UX.
