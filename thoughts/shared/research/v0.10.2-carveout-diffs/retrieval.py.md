# `backend/open_webui/routers/retrieval.py` — carve-out port-decision table

**Summary:** 30 logical hunks reviewed — **11 PORTED**, **17 DELIBERATELY-SKIPPED**, **2 N-A**.
**Config-migration verdict:** MIGRATED — no dead `app.state.config`/`PersistentConfig` references remain (fork built its own async per-key config shim, functionally equivalent to but not a literal port of upstream's `RetrievalConfig`). **NO CRASH RISK** from the config subsystem.
**Notable non-config finding:** `process_web` is missing upstream's `except HTTPException: raise` guard, so a 403 from `_validate_collection_access` gets masked as a 400 — see Follow-ups.

File was carved at "ours" (`git checkout --ours`) per plan decision D4 (`thoughts/shared/plans/2026-07-02-upstream-v0.10.2-merge.md`), because `integrations.py` hard-imports `submit_existing_file_to_pipeline` (fork-only distributed doc-pipeline code) and upstream's `save_docs_to_vector_db` gained a *required* `config` param that would have broken all sync/integrations callers. Two mandatory shims were then applied, plus the Phase 3 config-subsystem conversion.

## Follow-ups / risks

1. **Moderate — `process_web` masks 403 as 400.** `_validate_collection_access(..., access_type='write')` is called inside `process_web`'s `try` block (`retrieval.py:2251`) but the file lacks upstream's `except HTTPException: raise` guard (row 19), so a legitimate 403 Forbidden gets caught by the broad `except Exception` and re-raised as a 400 Bad Request. Worth porting just this guard independent of the rest of the RetrievalConfig-adjacent backlog.
2. **Low/pre-existing — `QueryDocForm` missing `hybrid_bm25_weight` (row 24).** `query_doc_handler` references `form_data.hybrid_bm25_weight`, a field `QueryDocForm` never declares. Confirmed present identically in the fork tip *before* this merge, so it is not a merge regression — but upstream's field addition is sitting right there unported and would fix it. Worth a one-line cherry-pick regardless of the rest of the config refactor being skipped.
3. **Backlog reminder — `loader.metadata` pass-through (row 16).** Plan explicitly flags this as "worth porting — feeds gradient-doc-processor." Currently absent.
4. **Backlog reminder — new web-search providers/config (rows 2, 10, 11, 20, 22).** serphouse, microsoft_web_iq, linkup, and `WEB_SEARCH_CONFIRMATION` are fully absent (imports, config keys, and `search_web` dispatch branches). Consistent, deliberate, and matches the plan's port-later list.
5. **Backlog reminder — `publish_event` progress events (rows 17, 26, 27, 28).** No `EVENTS`/`publish_event` usage anywhere in this file. If other carved-out files (e.g. `knowledge.py`, `files.py`) already emit these events, retrieval-side operations (file processed, collection deleted, vector DB reset, uploads reset) will not show up in any event-driven UI/audit trail that depends on them.
6. **Low — chunking quality regression vs upstream (row 14).** The improved backward-merge chunk algorithm and `token_transformers` splitter (with `RAG_TOKENIZER_MODEL`) are not present; fork's chunker is strictly the older, forward-only version. Not a bug, just a missed quality improvement.
